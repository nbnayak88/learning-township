Evidence boundary: OmniSpace is a fictional educational case. The case sources contain little operating-model detail for run operations; the teams, cost drivers and ownership rules below are new design. Nothing here is a record of a client implementation, an executed test or a realized benefit. Names marked synthetic carry the prefix RE-SYN and are new design. SAP product statements come from public SAP documentation reviewed 2026-11-10 and must be verified before real delivery.

1. The question this file answers

Who runs intelligent operations, who owns each service, and who sees what it costs?

What this file shows: a proposed team structure for OmniSpace, an ownership rule for every service in the Demo 06 landscape, a shift from ticket-based support to service ownership, and the cost drivers to make visible.

What it does not show: headcount, budgets, savings or any measured cost.

11. Hands-on exercise (synthetic data)

  1. Assign a named owner and an on-call role to each component in the register.
  2. Write the first lines of a runbook for the highest-criticality component.
  3. Rank the cost drivers by who can act on them and name a review date.
  4. Mark which team changes are needed from today's structure.
  5. Record open decisions in the run log.
