OmniVibe — Industry-Specific Regulation: Country-Anchored Design Questions

Demo 15 of the BTM11 Consumer Discretionary Ultimate Bootcamp demo series

SuccessLabs Academy · BTM11 · Consumer Discretionary (CD) · Ultimate (Level 5) · Bootcamp Version: 2026-11-10 · Demonstration material; not an enrolled course, certification or published pathway. Series baseline: Demo 01 case baseline · Related: Demo 02 · Demo 03 · Demo 04 · Demo 05 · Demo 06 · Demo 07 · Demo 08 · Demo 09 · Demo 10 · Demo 11 · Demo 12 · Demo 13 · Demo 14

Evidence boundary: OmniVibe is a fictional educational case. The case sources name headquarters countries but almost no regulations; this file points to regimes to verify and does not state legal conclusions. Nothing here is a record of a client implementation, an executed test or a realized benefit. Names marked synthetic carry the prefix CD-SYN and are new design. SAP product statements come from public SAP documentation reviewed 2026-11-10 and must be verified before real delivery.

1. The question this file answers

Which regulatory regimes touch the architecture, in the countries this case names, and what evidence would each need?

What this file shows: the countries the case names, the regimes to verify for each, which design element each regime touches, and the evidence slot each would need.

What it does not show: legal advice, a compliance assessment or a claim that any regime is met. Every instrument is a pointer to verify with counsel.

2. Case anchor (source facts)

Attribute Case baseline

Countries named by the case: London (United Kingdom) and Singapore, per the case profile.

Country rule for this series: only countries named in the case are used. No other country is assumed.

Illustrative trigger (source): A new associate lacks a completed onboarding and skills handoff while store readiness and channel information disagree (invented events that prompt discovery, per the case).

8. Hands-on exercise (synthetic data)

  1. List the data flows between the named countries (synthetic) and mark the owner of each.
  2. For two regimes, write the evidence slot and who supplies it.
  3. Walk the first tabletop test and mark who is told and in what order.
  4. Mark every statement in the file that still needs counsel to confirm.
  5. Record open decisions in the run log.

Three tabletop tests

A tabletop test is a paper walk-through, not a technical test of a running system.

Test Setup Expected finding
T1 Cross-border customer data Customer data moves between the UK and Singapore Transfer basis and residency recorded
T2 Consent mismatch A UK consent record is used in Singapore Per-country consent rule applies
T3 Unsupported claim A claim has no evidence Held
